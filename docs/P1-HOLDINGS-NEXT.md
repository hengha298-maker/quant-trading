# 下一阶段：真实持仓CSV、本地资产报告及V2衔接

## 已有基础与本次准备

复用P1现有CSV严格校验、华宝/银河匿名分账户、不可覆盖的UUID快照、本地HTML报告、失败行情审计；不重新搭建。已有导入和费用报告可以本地手动运行，步骤见[p1/README.md](../p1/README.md)。本次增加采集到本地报告的完整集成回归及`market_usage`共用权限判断。**本次尚未实现市值汇总报告、V2真实数据适配器、手机真实持仓访问或云同步。**

下一交付应先做“CSV预检确认→新持仓快照→本地资产分析报告”，再单独开发V2只读适配；不需要账户登录、交易接口或持续费用。

## 建议的独立开发任务与验收

1. 在P1新增本地CSV预检/预览，保留严格表头、匿名账户、数量/可卖/现金/成本校验及完整/部分录入声明。预检不写快照；用户本地确认后生成新版本，旧快照不可覆盖；拒绝异常时不落半份数据。复用现有工具环境，给出双击或简短命令入口。
2. 资产报告先展示真实录入事实：分账户现金、数量、可卖数量、券商成本及快照日期。不把未知变零，不用券商成本冒充市值，不用总数量推算可卖量；成本不等于累计收益。
3. 市值分析须另行实现资格判断：价格单位和不复权口径明确、数据通过校验，且行情与快照有清楚的日期对应关系。新浪当前不符合估值条件。缺一标的价格时全账户总资产/配置比例为未知，可展示有明确覆盖率说明的“已估值部分”，不能把部分市值称为总资产。跨账户或跨日数据不得悄悄合并。
4. 无真实流水不输出累计收益；无实际费率不将示例费用转成实盘建议；不做自动买卖。过期快照/行情保留日期并降级为历史参考，不能因报告刚生成而变成实时数据。
5. 先用虚构数据自动验收：华宝/银河、现金未知和真实零、部分/完整账户、不同日期、单标的失败、Sina观察可用但估值不可用、非法CSV、重复导入及回滚。真实验收由用户在电脑本地完成，**无需上传CSV、报告、路径或账户号码**。

## V2只读契约草案（本轮不改v2目录）

下一阶段适配器应从显式选择的P1快照/行情批次生成独立read model，最少包括：

| 分组 | 契约要求 |
|---|---|
| 身份与版本 | 契约版本、持仓snapshot_id、行情batch_id；禁止靠文件修改时间猜“最新” |
| 时间 | snapshot_as_of（现有仅日期）、snapshot_at=null、quote_as_of、fetched_at、report_generated_at分别保留；不补造日内时刻 |
| 账户事实 | anonymous account、broker、coverage、cash、positions(quantity/available/broker_cost/cost_basis)；Decimal数值用字符串，未知用null |
| 行情 | source、symbol、interval、status、adjustment、volume_unit、freshness、public provenance；只输出允许展示的字段，不把本机路径带到界面 |
| 使用资格 | 复用market_usage并另做估值资格判断；observed不等于可用于估值或交易；unavailable的派生金额为null并带原因 |
| 研究 | long_term与intraday独立，初期均“无法形成可靠建议/未验证”，不复用V1模拟账户信号 |

V2未来需显式区分演示/本地真实两种模式，真实模式不能缺数后回填演示价格。先做本地、授权只读展示；当前无服务、无端口、无真实导出。手机访问、身份认证、加密和云端只读同步作为后续独立安全验收，不因准备契约就直接复制私人文件进v2、Git仓库或PWA缓存。

每项独立提交和验收；失败可删除该版独立源码或选择前一份快照重新生成报告，不删除或覆盖历史数据。始终不改V1.1、Bark、定时任务或券商环境。
