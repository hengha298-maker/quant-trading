## K2 与 KL 的区别及 AKShare 兼容性

用户在 Windows 取得HTTP200、17915字节，正文以 `var KLC_K2_sh515450="K2/3rPX...` 开始。先前仅接受 `KLC_KL_sh515450`，因此在解码前被拒绝。这些是用户本机观察，本轮没有取得完整响应；17915字节不能推导日线条数。

核对的是已安装、固定版本 `akshare==1.19.1` 的 `akshare.stock.cons.hk_js_decode`，不是网络上其他版本。该解码器的 `d()` 首先用64字符表把每个字符读作6个低位在前的比特，读取12位类型和6位版本码（版本值为 `63 XOR 版本码`），再选择解码分支。**不是普通Base64字节流，也不能仅凭JavaScript变量名判断编码。**

本期明确接受以下组合，其余组合或版本失败关闭：

| 响应变量（仅sh515450） | 压缩头 | 类型/版本 | 1.19.1原解码器分支及区别 |
|---|---|---|---|
| KLC_KL_sh515450 | HX/… | 1479 / 0 | `_1479: D`：旧OHLC及累计成交量差分布局，流内价格精度/位宽、交易日步进 |
| KLC_K2_sh515450 | K2/… | 3466 / 0 | `_3466: O`：独立布局，支持动态精度、分离价格状态、amount和可选盘后字段、工作日掩码与显式结束控制 |

`K2/3rPX` 的前三字符即可确定3466/0，**不能凭这个短前缀解出完整行情**。K2不能通过换名交给旧1479分支；1.19.1本身已有3466分支。本地常量解码器文本的SHA256为 `39a599c94dde4df1c2eb0882d4bff9560160cfd52ead0797cebb04b3122c2f52`，方便复核这次研究依据。

原 `fund_etf_hist_sina` 读取等号右侧内容调用同一个 `d()`，并不根据变量名选择分支。因此代码层面兼容3466；本轮进一步用**真正安装的解码器和原API**运行两种人工编码样本。两条不同布局的测试比特流均还原成预先指定的3个虚构交易日和OHLCV，逐项相等；K2额外的amount也符合其布局。测试只替换下载传输，不替换解码器、原API或计算价格。

这些测试证明固定实现的编码兼容性，**不是515450最新真实行情验收**，也不是对行情价格的独立经济真实性背书。两种路径使用同一算法，仍需对实际响应的末日价格、范围与时效进行核对。

## 修复后的验证链

1. 仍仅请求固定HTTPS地址，检查HTTP状态、最终URL、长度和8MB上限。完整匹配允许的K2/KL变量及准确证券代码，拒绝追加脚本、其他证券、其他变量名。
2. 解析压缩头，核对类型、版本与包装组合；不支持时为 `SinaEncodingError`。解码执行仍只有固定本地代码，保持子进程、内存和超时限制。
3. 先校验**完整原始序列**的日期严格升序、无重复/未来值、有限正价格、OHLC关系和非负量，再裁剪区间。不先排序、不丢掉区间外坏行。
4. 把**下载的原始正文**交给原AKShare API，保留K2或KL变量名，不再重建成KL包装。核对完整原始行数、每行日期和OHLCV。原API不能处理的正文也会失败，不替它修写输入后宣称兼容。
5. 检查截至日期要求；过期为不可用。成功摘要显示格式、编码/版本、字节数、原始/选定范围及条数、区间首末日OHLCV、采集时间和响应SHA256。父进程再次检查边界价格、日期、数量及编码元数据。

日线仍采用北京时间16点和保守工作日候选，**未核验交易所日历**；节假日可保守拒绝。复权与量单位仍未核验，不跨来源拼接，不进入费用建议。任何失败返回 `unavailable`；探测不保存数据、不自动开启 `SINA_DAILY_VERIFIED`。

## ZIP 无 Git 的测试故障

`test_guard_rejects_private_artifacts` 原来只模拟 `git` 输出，未提供独立源码根与`.git`。在ZIP下，检查器正确进入文件系统扫描，模拟输出未被使用，导致“应拒绝虚构CSV”的断言反而得到0。生产检查器没有放宽；修复的是测试对外部目录状态的依赖。

现在Git模式测试使用临时源码根和虚构`.git`标记；另外新增真实子进程回归，在无`.git`、`PATH=''`、cp1252输出的ZIP布局中运行整套原14项测试。全套120项测试也在实际隔离ZIP副本中验证。

修复前后复现：同一个ZIP环境，旧测试单独运行 **1失败（0 != 1）**；修复后完整标准库测试 **109通过、11跳过，共120项**。跳过为6项Windows专用和5项可选真实解码器专项，未冒称通过。安装固定工具后，本地P1为 **114通过、6跳过，共120项**，其中6项编码专项全部通过；本地原PR分支完整pytest为 **182通过、6跳过**。

Windows/Linux CI会在本轮提交上运行，最终结果见原PR Checks。完整依赖回归包含固定AKShare和MiniRacer，实际执行解码与原API专项；标准库独立CI明确跳过5项可选测试。Windows桌面手动联网结果仍需用户复验，不能由离线CI代替。
