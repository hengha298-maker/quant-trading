# Tailscale 1.104.2 自动停止修复与最短复验

本次基于原 PR #5 的 98d5425 修复，只修改 V2 及其专用 CI。真实数据文件、P1 校验、V1.1、Bark 和定时任务保持原样。

## 确认的代码问题和修复

1. 旧版在启动和每次 `_watch` 检查中，使用整个 `Device` 对象相等来确认授权。这同时比较了 **HostName 显示名**及 **IP 列表顺序**。设备仍为同一稳定 ID、同一用户和同一完整 IP 集合时，仅显示名/顺序变化就会误停。新版明确比较稳定设备 ID、用户 ID、登录名和完整 IP 集合；所有地址仍须一致，不允许增删或替换。显示名 `localhost` 不能证明设备是谁，核对 iPhone 的 Tailscale IP 后再授权。
2. 旧 `_watch` 丢弃所有具体错误，CLI 包装器还把退出/超时/JSON错误吞成同一错误。新版保留失败分支，只记录白名单固定码；控制台每次失败只打印一行固定码，窗口显示解释并提供“复制诊断码”。不输出持仓、配对码、Cookie、设备身份、私网 URL、本地路径或原始 CLI 内容。
3. 新版在显示“已启动”前先运行一次与监督循环相同的完整检查；绑定本次前台 SessionID，之后会话变化也会撤销。清理结果单独记录，不覆盖最初失败原因。

这些是已经复现并由回归测试确认的代码缺陷。**98d5425 未保留当时分支，无法事后确定用户那一次究竟是哪项失败。** 若仍出现自动停止，新版的固定码可以精确区分，无需提供私人原始状态。

## 已核对 1.104.2 的行为

已核对官方 v1.104.2 的 [serve_legacy.go](https://github.com/tailscale/tailscale/blob/v1.104.2/cmd/tailscale/cli/serve_legacy.go)、[serve_v2.go](https://github.com/tailscale/tailscale/blob/v1.104.2/cmd/tailscale/cli/serve_v2.go)、[ServeConfig](https://github.com/tailscale/tailscale/blob/v1.104.2/ipn/serve.go) 和 [PeerStatus](https://github.com/tailscale/tailscale/blob/v1.104.2/ipn/ipnstate/ipnstate.go)。Windows 使用同一套 Serve/状态代码。

- 普通 `tailscale serve status` 仍不展示前台 Foreground 配置，可能在分享正常时显示 `No serve config`；不能单凭这条输出判断服务进程已退出。
- 本程序只使用 `tailscale serve status --json`，要求唯一的 Foreground、HTTPS8443和本次精确代理目标；不接受后台配置或额外路由。JSON结构未知时拒绝，不猜测兼容、不忽略字段。
- 前台 Serve 的生命周期绑定 WatchIPNBus 会话，进程退出或会话关闭后配置会被移除。新版分别识别进程退出、配置消失、配置变化和会话替换。
- HostName 是显示元数据，不是唯一身份。Online 表示控制平面在线，**不是 Active 或最近握手**。仍要求电脑和授权 iPhone 在线；离线立即撤销，不用历史活跃记录绕过。

## 最短 Windows 复验

1. 旧窗口若仍在，点“停止分享”并关闭。下载 PR #5 新 ZIP，解压到新目录；不用改 P1、持仓目录或 Tailscale 设置。
2. 双击新目录 `v2\iPhone真实持仓只读.cmd`。升级后的首次启动需选择一次 P1 源码、同一份快照和两份行情；**不需要重新导入或复制数据**。路径选择仅留在进程内存，关窗后不持久保存。
3. 刷新选择自己的 iPhone，核对 Tailscale IP，点“启动分享”，确认设备。Safari 打开窗口提供的 HTTPS 地址并输入新配对码。
4. 若又自动停止，**不要关控制窗口，不要重新选文件**。点“复制诊断码”，只把该固定代码反馈给 Codex。重新连接两端 Tailscale 后可直接再点“启动分享”；原文件选择保留。刷新设备也会保留原选择，前提是稳定身份和完整IP集合仍一致；若地址或身份变化，必须重新核对设备。

需要时点“更新配对码”废除旧会话；结束点“停止分享”。不要粘贴完整 status JSON，不要发送私网地址或配对码，不要忽略 Safari 证书警告。无需重复大量人工虚构测试。

## 固定码含义

| 固定码 | 明确含义 |
| --- | --- |
| `serve_exited` / `serve_failed` | 本次前台进程分别以零/非零状态提前退出，不输出原始 stderr 或退出内容。 |
| `serve_config_missing` | 进程检查尚未看到退出，但 JSON 配置已经为空。 |
| `serve_configuration_changed` / `serve_session_changed` | HTTPS/代理/路由/Funnel配置不再匹配，或前台会话被替换。 |
| `serve_config_unknown` / `serve_schema_unsupported` | 配置JSON类型或字段结构与已核对契约不一致，拒绝运行。 |
| `tailscale_status_invalid` | 设备状态结构无法解析或关键类型不符，拒绝运行。 |
| `tailscale_self_offline` / `tailscale_self_key_expired` | Windows设备离线或密钥失效。 |
| `device_offline` / `device_unavailable` | 原iPhone离线或没有出现在可核验列表。 |
| `device_identity_changed` / `device_addresses_changed` | 稳定身份所属用户不匹配，或授权完整地址集合变化。 |
| `device_key_expired` / `device_not_ios` / `device_tagged_or_shared` | 设备密钥、平台或标签/分享状态不再符合授权要求。 |
| `tailnet_dns_changed` / `magicdns_required` | 电脑DNS名称变化，或不能确认有效私网名称。 |
| `cli_config_timeout` / `cli_status_timeout` / `cli_version_timeout` | 对应CLI检查超时，仍会撤销分享。 |
| `cli_*_exit` / `cli_*_json` / `cli_*_encoding` | 对应命令失败、返回非法JSON或编码；不记录原始输出。 |
| `stop_unconfirmed` | 数据接口已关闭，但不能确认 Serve 清理状态；退出 Windows Tailscale 确认断开。 |

其他固定码也可直接复制反馈；任意未登记异常一律转成固定内部码，原始异常文字不进入诊断。保留全部鉴权、whois逐请求核验、HTTPS、撤销/清屏和无持久缓存边界。不使用 Funnel、公网、HTTP 降级或放宽身份来保持运行。

## 自动化覆盖

新增监督回归覆盖 1.104.2/1.90.9版本行、Foreground JSON、显示名/地址顺序变化、完整身份/地址不可变、Windows/iPhone离线及密钥、CLI错误保真和脱敏、15种监督失败后的会话撤销及数据清空、启动成功前的完整检查。

Windows专用测试实际构建控制窗口，选择虚构文件后模拟失败，复制诊断并直接重试，验证文件选择没有重复弹出。所有数据、设备、路径和CLI均为测试替身；不把这些结果称为用户iPhone实机连接已成功。
