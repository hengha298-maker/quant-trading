# 4b8fdce：HTTPS已到应用，但返回device_denied

`check_whois_failed + device_denied` 来自Windows直接调用whois身份验证，不经过Safari、XFF或用户请求头。因此这组结果证明至少一项whois条件被拒绝。手机已经收到应用JSON，也证明那次请求走过了DNS、TCP/TLS和Serve转发；不再要求重装Tailscale、重下P1或重复网络命令。

旧版把所有条件合在一个OR里，统一只给device_denied，**仅凭旧码无法确定是哪一项真实字段失败**。本次没有凭猜测转换ID或推定授权；修复的是精确拒绝原因、启动前一次自动报告及请求诊断漏记。真实iPhone是否通过仍需实际验收，不把离线结构测试称为实机成功。

## 已核对的官方1.104.2结构

| 字段 | 官方含义/表示 | 本程序要求 |
| --- | --- | --- |
| status Peer.ID / whois Node.StableID | 同一个StableNodeID字符串 | 精确相等，不去前缀。 |
| Peer.UserID / Node.User | 同一个数值UserID | 严格整数且等于选定所属用户。 |
| UserProfile.ID | 数值UserID，无省略tag | 严格整数且与选定用户一致；不接受字符串或bool替代。 |
| status User表 | JSON对象键是字符串，值内ID仍是整数 | 字符串索引正确，不改变身份值。 |
| LoginName | status和whois均取可信用户档案 | 精确一致；更新/不一致时仍拒绝，不接受别名猜测。 |
| MachineAuthorized | bool，false会因omitempty省略 | 必须显式true；缺失、false、null、错误类型分别报告并拒绝。 |
| Addresses | Node直接地址的host prefix，status从单IP项提取裸IP | 对请求地址核验精确/32或/128，不以AllowedIPs路由授权。 |
| KeyExpiry | Node使用omitzero；PeerStatus使用可空时间指针 | 保留前轮仅已核验1.104.2可省略的规则；null/类型错误/无效或过期仍拒绝。 |
| Expired/Tags/Sharer | 过期、标签及分享状态 | 严格核验，不用存在peer、ping成功或HTTPS可达推定授权。 |

依据：[tailcfg定义](https://github.com/tailscale/tailscale/blob/v1.104.2/tailcfg/tailcfg.go)、[status映射](https://github.com/tailscale/tailscale/blob/v1.104.2/ipn/ipnlocal/local.go#L1628)、[whois](https://github.com/tailscale/tailscale/blob/v1.104.2/cmd/tailscale/cli/whois.go)、[Serve头生成](https://github.com/tailscale/tailscale/blob/v1.104.2/ipn/ipnlocal/serve.go#L1088)。本版支持的ASCII登录名在Serve头中原样输出；Unicode的RFC2047表示不被猜测解码放行。

## 本轮实际改动

- `identity_failures`对同一次可信whois结果收集**所有**失败固定码；`verify_identity`仍任一失败即拒绝。稳定ID、Node.User、Profile.ID、LoginName、MachineAuthorized、地址、到期、标签及分享状态均有单独缺失/类型/不匹配码，不含字段原值。
- 启动时对选定设备的批准地址自动预检，在读取P1文件、创建分享接口前就报告全部阻断条件。失败窗口可直接复制完整码，周期刷新不会再把多项覆盖成第一项；文件选择保留。
- X-Forwarded-For和Tailscale-User-Login分别报告缺失、重复、非法或不匹配。原Loopback/秘密路径/HTTPS/Host/Origin/Funnel拒绝及逐请求whois全部保留。
- 诊断补上可信代理但尚未归属的请求层。合法IPv6文本先规范化再决定是否记候选，缺失/重复/非选定XFF不再被静默丢弃，也不会被称为已认证iPhone。
- 本次分享的有限**固定码集合**持续保留，输出加`history_`前缀。当前短窗口仍与历史分开；窗口外403不再完全丢失。只保留码，无IP/身份/头值/路径/URL/持仓/Cookie/配对码或时间线；停止时清空。已确认Self地址的自检不计入手机历史。

旧`phone_request_not_observed`只意味着当时短窗口没有满足候选条件的记录，可能是点击前/窗口后已发生403，或头不满足旧候选规则；不能推翻手机实际收到403，更不能拿它判断网络不通。

## 最短复验

使用新PR #5代码启动原真实只读入口，沿用原P1源码和原文件，不重新下载或导入P1。点“启动分享”即可自动列出全部身份阻断码；若拒绝，**无需再测试手机或运行网络命令，直接点“复制诊断码”反馈固定码**。若全部通过才启动分享，再用Safari正常配对查看。同一窗口重试不重选文件。

如果需要查看已发生请求的归属码，原一键诊断会附本次Share的`history_`摘要，不必赶短窗口时序。外部HTTP响应仍是通用403，不向未授权设备披露详细原因。
