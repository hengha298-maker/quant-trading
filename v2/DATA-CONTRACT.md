# V2 只读展示数据约定

本约定描述当前 `demo-data.js`、`model.js` 和页面之间的边界，以及为未来 P1 展示保留的映射函数。它不是已经接通的数据导入或云同步接口。**当前页面只接收虚构演示，不能从界面导入 CSV、JSON 或真实持仓。**

## 一、先区分数据模式

| 模式 | 当前用途 | 能否加载进当前四页界面 |
| --- | --- | --- |
| `demo` | 仓库自带且冻结的公开虚构演示对象 | 可以；启动时由 `assertDemo()` 检查标识及非操作状态 |
| `historical` | `adaptP1()` 为未来展示返回的历史持仓对象 | 不可以；当前 `assertDemo()` 明确拒收 |
| `paper`、`live` 等其他模式 | 本原型没有实现 | 不可以；不把模拟账户当成真实账户 |

演示对象使用 `schemaVersion: 1`、`datasetId` 的 `demo-` 前缀、`sourceLabel: "虚构演示数据"`。策略及报告的 `actionable` 必须为 `false`。这些检查用于防止误接线，不构成通用数据校验、真实性证明或安全认证。

页面没有价格信号或委托逻辑；`freshness()` 即使返回 `fresh`，也始终返回 `actionable: false`。时间落在一个窗口内不等于数据可信，更不等于策略已经通过验证。

## 二、当前展示对象的含义

| 字段 | 含义和规则 |
| --- | --- |
| `holdingsAsOf` | 持仓日期；日期与日内时刻分开处理 |
| `holdingsTimeKnown` | 当前为 `false`，不得补成某个交易时刻 |
| `quoteAsOf` | 参考行情时间；演示值是固定虚构样例，缺失时为 `null` |
| `generatedAt` | 报告生成时间；不会随着打开或刷新页面改写 |
| `syncedAt` | 最后同步时间；当前为 `null`，显示未接入，不能用报告时间替代 |
| `transactionHistoryComplete` | 当前为 `false`，不能重建真实累计收益 |
| `accounts` | 分券商账户展示；现金、数量和可卖数量不跨账户调剂 |
| `strategies` | 长期加仓及日内做T的独立研究说明、限制、验证状态 |
| `reports` | 带自身时间、数据集和策略版本的虚构历史记录 |
| `features` | 四项功能预留；`enabled: false`，不是可调用的后端能力 |

账户的 `coverage` 为 `partial` 或 `complete`。`complete` 只代表录入完整性声明，不证明账户录全或数据核验完毕。当前银河示例 `cash: null`，因此资产总数只标作“已知资产”，不标作完整投资资产。

持仓字段如下：

| 字段 | 展示含义 |
| --- | --- |
| `symbol`、`name`、`kind` | 证券标识、显示名称、`stock`／`etf` 类型 |
| `quantity` | 快照总数量，股票按股、ETF 按份展示 |
| `available` | 快照中的历史可卖数量；不代表现在可以卖出 |
| `brokerCost` | 券商显示成本，可未知，也可能为负；不是累计收益或完整现金流成本 |
| `referencePrice` | 演示汇总用的虚构参考价格；P1 映射不提供行情，因而为 `null` |

`null` 表示未知，真实的 `0` 表示已知为零。格式化辅助函数也将 `undefined` 和空字符串显示为未知，但这不意味着上游输入允许空字符串充当有效金额。全为未知的金额合计仍为未知，不变成零；空持仓列表的市值为零。存在未知现金或价格时，已知部分可以作展示小计，必须同时保留不完整状态。

## 三、时间不能凭空补齐

日期使用有效的 `YYYY-MM-DD`；有时刻的时间戳需要显式时区，如 `2026-10-19T15:00:00+08:00` 或 `Z`。界面统一以北京时间展示。

仅有日期时显示“未记录日内时刻”，不补 `00:00`、收盘时间或当前时间。空时间显示未记录；无时区、非法日期、未来时间分别保留无效或不可用状态。`freshness()` 的默认 300 秒只是展示辅助函数的默认窗口，不是已经验收的行情 SLA 或做T有效期。

历史报告保存自己的行情、持仓和生成时间，不继承首页当时的样例时间。未知同步时间不能解释为同步成功。

## 四、P1 的未来展示映射

`adaptP1(snapshot, now)` 只接受已经由 P1 校验器接受的 v1 快照对象。它不读取文件、不解析 CSV／JSON、不执行路径检查、不请求行情，也不修改传入对象。它不改变 Draft PR #3，当前页面不会调用它来加载真实数据。

映射前仍必须由 P1 执行其完整校验及本地存储策略。浏览器中的防御性字段检查不能替代 P1 对重复 JSON 键、文件大小、数值精度、来源及路径的检查；即使 P1 结构校验通过，也不证明数据来源真实或账户已经录全。

### 输入形状

下面只示意字段结构，所有标识和数值均为虚构：

```json
{
  "schema_version": 1,
  "as_of": "2026-10-19",
  "transaction_history_complete": false,
  "accounts": [
    {
      "account": "EXAMPLE_ONLY",
      "broker": "虚构券商",
      "coverage": "partial",
      "cash": null,
      "positions": [
        {
          "symbol": "600900.SH",
          "kind": "stock",
          "quantity": 300,
          "available": 200,
          "broker_cost": "25.80",
          "cost_basis": "broker_display"
        }
      ]
    }
  ]
}
```

映射采用明确版本和精确字段集合：顶层、账户及持仓均不接受额外或缺失字段。未来升级输入 schema 时应新增明确适配与测试，不能自动猜测字段、吞掉新字段或默认为 v1。

当前防御性检查包括：

- 仅支持 `schema_version: 1`；`as_of` 为有效日期，不能晚于北京时间当天；`transaction_history_complete` 仅支持 `false`。
- 账户标识不得重复，同账户证券不得重复，同证券跨账户的类型必须一致。
- `coverage` 仅支持 `partial`／`complete`；完整账户不能使用未知现金，但允许现金为零、持仓为空。
- 数量是安全整数，总数量大于零，历史可卖量在零与总量之间；这只是结构约束，不验证当前 T+1 额度。
- 现金为非负金额或 `null`；券商成本可为带符号金额或 `null`，并要求 `cost_basis: "broker_display"`。
- 非有限数、无效数字文本和超出映射限制的数值会被拒绝；不把空字符串转换为零。

### 输出不会冒充当前建议

| P1 字段 | 映射结果 |
| --- | --- |
| `schema_version` | `schemaVersion: 1` |
| `as_of` | `holdingsAsOf`，并固定 `holdingsTimeKnown: false` |
| `account` | 账户 `id` |
| `broker_cost` | `brokerCost`，保留未知或负成本的含义 |
| `quantity`、`available` | 按快照值保留；不自动结算、不推断当日买入或当前可卖量 |
| 没有行情、生成或同步时间 | `referencePrice`、`quoteAsOf`、`generatedAt`、`syncedAt` 均为 `null` |

结果固定为 `mode: "historical"`、`displayOnly: true`、`actionable: false`，来源标签为“P1 历史快照（需上游验证）”。它没有策略、报告或演示数据集标识，不能直接替换完整页面数据；`assertDemo()` 会拒收此结果。

## 五、金额精度与建议边界

P1 上游仍应使用 `Decimal` 等明确的十进制规则处理真实金额、费用和资金约束。此处 JavaScript 使用 `Number` 与 `Intl.NumberFormat` 作只读格式化和演示小计，会转换十进制字符串，不承诺账务精度或逐位无损往返。

现金合计使用两位小数；单位成本通过独立 `price()` 格式化保留可用小数（最多十二位），例如 ETF 成本 `1.046` 不显示成 `1.05`。演示参考价的显示精度不是已核验的证券交易规则。

**不要把前端小计返回给上游当作余额、费用、预算、委托价格、交易数量或可执行条件。** 任何后续真实资金计算都应在独立上游完成并经过校验；前端只展示结果和质量状态。数量格式化、时效判断或可卖量的结构检查，都不能替代账户核验、交易规则、费用模型与策略验证。

## 六、接入真实数据前必须重新验收

当前 `sw.js` 会缓存白名单内的公开 `demo-data.js` 和界面资源；它不是个人账户缓存方案。**禁止只把演示文件内容换成真实持仓后沿用此缓存、预览服务器或公开访问方式。**

后续真实数据应使用独立的数据模式、认证授权、受保护的访问与明确缓存策略；个人报告默认不进入公开离线缓存，并验证旧缓存清理和演示／真实来源切换。上传、身份验证、原子发布、版本冲突保护、手机修改持仓均尚未实现。相关能力需要单独开发和验收，不能由本约定推导为已具备。

当前预览器只接受 GET／HEAD 并提供明确白名单资源；没有导入、上传、持仓写入或云端 API。后续集成应继续保留 V1.1 模拟账户、PR #3 数据基础与 V2 展示之间的隔离。已有测试及未验证范围见 [VALIDATION.md](VALIDATION.md)。
